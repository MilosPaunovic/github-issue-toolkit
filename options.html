Welcome

GitHub Issue Toolkit adds what GitHub's lists and Projects views leave out: badges for custom issue fields, issue age and pull requests, a kanban board for epics, sub-issue progress that respects the view's filters, who each contributor is and what they already hold, a panel of pinned epics and search from the address bar. Most of it reads GitHub through its API, so the first step is a token.

Where to find things

Each tab has a Save button at the bottom. Nothing leaves your browser except requests to api.github.com.

GitHub access

Field values are read through the GitHub API. The token is stored in this browser profile only and is sent to nothing but api.github.com. Fields with "Organization only" visibility need a token of an organization member.

Recommended: a classic token with the repo scope. If the organization enforces SSO, open "Configure SSO" next to the new token and authorize it for that organization. A fine-grained token also works: set the organization as resource owner, pick the repositories, and under Repository permissions set Issues to Read-only.

Fields to show (optional)

Names of the issue fields to display, matched case-insensitively against the fields defined by the organization. Badges appear in this order; single-select values use the option's colour. An entry starting with label: shows labels instead: label:area/* every label starting with area/, label:bug only that one, in the badge colour nearest to the label's.

Press Enter or , to add a field, Backspace or the × button to remove one. Leave it empty to show no field badges; the rest of the extension works without them.

Issue age

Adds a badge with the time elapsed since the issue was created, next to the field badges, on sub-issue lists and on project table and board views.

The badge turns yellow past this age. 0 turns the highlight off. Default 90.

An issue younger than the unit reads today, this week or this month. Hovering the badge shows the exact age in months and days and the creation date.

Pull requests

Badges on the pull request list, next to the labels of each row. Everything comes from the same read-only API access as the field badges.

Epic kanban

Adds a List and Kanban toggle above the sub-issues list of an issue. The board reads every field the sub-issues carry, not only the ones above: you pick the field that forms the columns and the one that orders the cards inside each column, and both choices are remembered. Columns follow the order the organization gave the field's options. Filter the board down to one value of any dimension to see a single sprint or priority at a time, or hide the closed sub-issues with the checkbox in the toolbar.

Dragging writes to GitHub: it sets the field value, or closes and reopens the issue. The token needs write access to the issue's repository (the repo scope for classic tokens, Issues: Read and write for fine-grained ones). Nothing is written unless you drag a card.

Sub-issue progress

On a Projects table grouped by parent issue, GitHub's bar in each group header counts every sub-issue of an issue, including the ones the view hides with a filter or a slice. This replaces it with one that counts only the sub-issues inside the scope the view is narrowed to and shows the scope as tags, for example 14 / 18 done followed by release:2.1. The Sub-issues progress column keeps GitHub's own bar.

The field whose value narrows the count, or several separated by commas, Release, Owner for example, matched case-insensitively. Each value is read from what the view is sliced by, or from a release:2.1 term in its filter, and a sub-issue must have all of them. When the view is narrowed to none of them, GitHub's own bar stays. Leave it empty to count every sub-issue.

A sub-issue counts as done when this field has this value, Stage and Done for example. Leave both empty and a closed sub-issue is a done one. Needs a token that can read issue fields, like the badges.

Issue sidebar

A small button between the issue and its sidebar hides the whole metadata column, assignees, labels, type, fields, projects and the rest, giving the issue body and the kanban board the full width. The button stays in the same place either way, and what you choose holds on every issue until you press it again.

Takes GitHub's own Projects box, with its status and fields, out of the sidebar on every issue, while the rest of the sidebar stays. The issue remains in its projects; only the box is hidden.

Contributor button

Adds a small button after a person's name on an issue or pull request. Press it to see who they are to this repository, new, returning or a regular, and what they already hold: pull requests open, merged or closed without merging, and issues assigned to them. Handy before you reply to a stranger or hand someone one more thing. Nothing is looked up until you press the button, each person is looked up once, and the answer stays until you close the tab.

It looks like this next to a name: Contributor and, once pressed, First PR here

Asks GitHub once for every name on the page, in a shared request, and shows Member in place of the button for those who belong to the organization. Nothing else about them is read until you press the button.

Costs one request when an issue opens, and shows the author's status on sight. Everyone else is still looked up when you press their button. The sidebar gets no buttons, only names in the conversation do.

Statuses and limits

Two numbers decide what the button says about someone. Defaults are 5 and 1.

Organization panel

At the top of a person's profile, a panel for each organization you name, in that organization's colours where it has some, with what the person has done there: pull requests open, merged and closed without merging, issues opened and how many are still open, pull requests reviewed, and issues assigned to them, open and done. Each number links to the matching GitHub search. It is read once per person and organization when the profile opens, in one request, and kept until you close the tab.

One or more organization names, separated by commas, up to three. Nothing is shown until at least one is named. The status beside the name, Member, Regular contributor or Contributor, uses the same regular limit as the contributor button.

The card the button opens has the numbers for the repository and for the whole organization, split into sections for pull requests and issues, each a link to the matching GitHub search, then the open issues with the pull request that closes each, two in view and the rest below a scroll, and how old the answer is with a refresh button beside it. Your own name gets no button. Counts cover the repositories your token can read, so a fine-grained token limited to a few repositories sees only those.

Pinned issues

A pin button in GitHub's top bar, next to the notifications bell, opens a panel with your pinned issues, for example epics. From there you can copy the reference or make the issue you are looking at a sub-issue of a pinned epic. Linking writes to GitHub, so the token needs write access to the issue's repository (the repo scope for classic tokens, Issues: Read and write for fine-grained ones).

Address bar search

Type @gh and a space in the address bar, then a shortcut name and the words to look for, for example @gh repo flow. Each shortcut searches one kind of item and adds its qualifiers to your words, so org:acme keeps the search inside one organization. A shortcut name on its own, @gh pr, lists what its qualifiers match right away. Text that does not start with a shortcut name goes to the default shortcut. Results appear as you type; Enter on the text itself opens the GitHub search page.

NameIconSearchesQualifiersDefault

Qualifiers use GitHub search syntax, for example org:acme is:open or repo:acme/webapp. Repository names inside an org: or user: also match on any part of the name, so app finds webapp. With one repo: qualifier, a number such as #1234 goes straight to that issue or pull request. The icon is optional, an emoji such as 📦 or 🔀, shown before each result of the shortcut: the browser puts the same magnifier in front of every suggestion and lets no extension change it.
