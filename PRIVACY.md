# Privacy policy

GitHub Issue Toolkit is a browser extension that displays the values of GitHub custom issue fields on issue pages.

## Data the extension handles

- **GitHub personal access token.** You enter it on the extension's settings page. It is stored with `chrome.storage.local`, on your device only, and is sent exclusively to `https://api.github.com/graphql` in the `Authorization` header. It is never sent anywhere else. All requests read data (issue field values, labels, creation dates, the sub-issues of an issue you view as a board, the state and field values of the sub-issues behind a progress bar, the title and type of issues you pin, the standing of a person whose contributor button you press, and the search results for what you type after `@gh` in the address bar), with three exceptions: when you click **Link** in the pinned issues panel, the extension makes the current issue a sub-issue of the pinned one (`addSubIssue`), when you drag a card to another column on the kanban board, it writes that column's value to the issue (`createIssueFieldValue`, `deleteIssueFieldValue`) or closes and reopens the issue (`closeIssue`, `reopenIssue`), and when you tick comments in the assignment requests box and confirm, it marks them as outdated (`minimizeComment`) or, with Undo, brings them back (`unminimizeComment`). Nothing is written without that click, that drag or that confirmation.
- **Issue and pull request references.** For the issues and pull requests visible on the page you are viewing (sub-issue lists, project tables and boards, pull request lists), the extension sends the repository owner, repository name and number to the GitHub API to fetch the field values, labels, creation dates, and for pull requests the author's relation to the repository, fork origin, size and merge state. With the sub-issue progress on it sends the owner, name and number of the issues that carry a progress bar to count their sub-issues, reading only their states and the field values the scope and done settings name. With the kanban board open it sends the owner, name and number of the issue you are looking at to read its sub-issues: their numbers, titles, states, types, assignees, creation dates, field values and labels. Results are kept in memory for a few minutes and are discarded when the tab closes.
- **Profiles you open.** With the organization panel enabled and organizations named in the settings, opening a person's profile sends that login and each named organization to the GitHub API, to count the pull requests that person has open, merged and reviewed, the issues they opened and are assigned there, what they commented on, and whether they belong to the organization, and to read the titles and references of up to twenty of their open pull requests and up to twenty of the open issues assigned to them. It is a read, and the result is kept in memory until the tab is closed and, in the extension's session storage, for ten minutes, so that another tab or a reload does not ask again.
- **A pull request you open.** With related work on, opening a pull request sends its owner, repository and number to the GitHub API, to read its title and description, the issues GitHub has linked to it, the cross-references on its timeline and, for the issues it closes or names, the title, state and number of the pull requests that close or mention them. A second read looks up the issues and pull requests its description names. Both are reads, and the result is kept in memory until the tab is closed.
- **Comments of an issue you open.** With the assignment requests box enabled, opening an issue that has an assignee sends its owner, repository and number to the GitHub API, to read the author, the text, the date and the id of its comments, up to three hundred, who it is assigned to, and whether the repository is private, since the box is not shown for a private repository unless you ask for it. It is a read, and the result is kept in memory until the tab is closed. When you tick comments and confirm, the extension marks them as outdated (`minimizeComment`), and with Undo brings them back (`unminimizeComment`); nothing is written without that confirmation.
- **Usernames you press.** With the contributor button enabled, the logins of the people named on an issue or pull request, up to two hundred, are sent with the organization in the page URL in a shared request to the GitHub API, to tell which of them belong to the organization, so that members are left out or marked at once, whichever you choose for members in the settings. Pressing the button next to a username on an issue or pull request sends that login and the repository and organization in the page URL to the GitHub API, to count the pull requests that person has open, merged and closed without merging and the issues assigned to them, open or finished, for the repository and for the organization, and whether that person is a member of the organization, and to read the titles and references of up to twenty five of their open issues together with the pull requests that close them. If you also switch on reading the author automatically, the same read happens for them when an issue opens. It is a read, and the result is kept in memory until the tab is closed and, in the extension's session storage, for ten minutes, so that another tab or a reload does not ask again. Who belongs to an organization is kept there for six hours. Session storage lives in memory only, cannot be read by web pages, and is emptied when the browser closes or when you change the token. Your own login is read once so the button can skip your name.
- **What you type after `@gh` in the address bar.** Once you type the `@gh` keyword and a space, the words that follow and the qualifiers of the matching shortcut are sent to the GitHub search API to show suggestions, as you type. For a shortcut with an `org:` or `user:` qualifier, the extension also reads the names, descriptions, links and last push dates of up to five hundred repositories of that owner as soon as you type the keyword, kept for ten minutes in the browser's session storage, which stays in memory and is cleared when the browser closes. Nothing is sent for anything you type in the address bar without the keyword.
- **Settings and pins.** Your list of field names, the age badge, pull request badge, sub-issue progress (the scope fields and what counts as done), contributor load, address bar shortcuts, kanban, sidebar and pinned issues preferences (including whether the board or the list is shown, the field the board groups by, the one it orders by, the filter, whether closed sub-issues are hidden, whether the issue sidebar is folded away, whether its Projects section is hidden, whether related work on pull requests is shown, and whether the profile panel, the assignment requests box and related work start folded down to their header), and the issues you pin (repository, number, title, type) are stored with `chrome.storage.local` on your device.

## Data the extension does not handle

- No analytics, telemetry or crash reporting.
- No cookies, no tracking, no third-party services.
- No data leaves your browser except the GitHub API requests described above.

## Permissions

- `storage` - saves the token, the field list and your preferences locally, and keeps what was read about a person in memory for a short while.
- Host permission `https://api.github.com/*` - reads issue field values, labels, creation dates, the sub-issues behind the kanban board and the progress bars, pinned issue details, the contributor status and load of a username you press and the address bar search results through the GitHub GraphQL API, and performs the sub-issue link you request from the pinned issues panel and the card move you perform by dragging.
- Content script on `https://github.com/*` - finds sub-issue rows, project table rows, board cards and pull request rows, renders the badges, the kanban board and the sub-issue progress, adds the contributor button next to usernames, adds the button that hides the issue sidebar, optionally hides the sidebar's Projects section, and adds the pinned issues button to GitHub's header.

On Firefox, access to `github.com` and `api.github.com` is granted by you after installation (the settings page asks for it once); the extension does nothing until then.

## Removing your data

Clear the token and remove all pins on the settings page, or uninstall the extension. Uninstalling removes everything the extension stored.
